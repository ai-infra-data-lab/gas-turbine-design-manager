# Turbine Design Desk 0.1

ガスタービンの設計情報を案件・部品・設計案ごとに整理するローカルアプリです。計算機能は含みません。Python 3.10以上の標準ライブラリのみを使用し、追加パッケージ・アカウント・インターネット接続は不要です。

## GitHubから取得

```powershell
git clone https://github.com/ai-infra-data-lab/gas-turbine-design-manager.git gas_turbine_manager
cd gas_turbine_manager
python server.py
```

Python 3.10以上が必要です。公開版に個人の設計DB・試験用DBは含みません。数値入りの架空サンプルは `start_sample.bat` または `python create_samples.py` で生成できます。

独立した[一軸サイクル計算アプリ](https://github.com/ai-infra-data-lab/gas-turbine-cycle-app)と Blade Designer の出力は、「設計成果物」から案件に登録できます。

## 起動

`start.bat` をダブルクリックします。ブラウザに `http://127.0.0.1:8770` が開きます。終了は起動したウィンドウで Ctrl+C です。別ポートの場合は `python server.py --port 8771` を使用します。

## 最初の操作

**数値入りサンプルと画像付きマニュアル**: `start_sample.bat` をダブルクリックすると、通常データと別のDBで2つの架空の設計案を開きます。サンプルURLは `http://127.0.0.1:8772/`。左メニューの「サンプル操作マニュアル」、または `docs/manual/index.html` から操作例を参照できます。

基準案Aは目標100 kW・60000 rpm、比較案Bは55000 rpmで、インペラ外径・効率目標にも違いを付けています。すべて操作説明用の架空値で、計算結果ではありません。初期値は `create_samples.py` で生成し、ブラウザで変更・保存・復元・添付の実演を行っています。既存のサンプルDBがある場合は上書きしません。`samples/A_基準案.json` と `samples/B_低回転案.json` は、通常アプリへ取り込める添付込みの初期データです。DBの履歴はJSONには含まれません。

1. 「新規プロジェクト」で案件名を入力します。「一軸ガスタービン」を選ぶと8部品と未設定の要求項目を作成します。計算値・架空の性能値は生成しません。
2. 「基本情報を編集」で用途、構成、担当、目的、状態を記録します。
3. 「部品構成」で部品を追加・編集・並べ替えます。部品を選択すると、その部品の「仕様・設計値」が開きます。
4. 仕様・設計値は項目名、値、単位・定義、出典・根拠、備考を登録します。値は文字列で、空欄や範囲も扱えます。単位換算・妥当性判定は行いません。
5. 「資料」でファイルのコピーや参考URLを登録します。関連部品も指定できます。「案件全体」では全資料、「部品」ではその部品の資料を表示します。
6. 「設計メモ」で判断理由・検討事項などを残します。
7. 「設計案を複製」で代替案を作り、「設計案の比較」で基本情報・要求仕様・部品情報・部品設計値を比較します。

## 要求・検証（MBSE）

案件の「要求・検証」で、運用目的・運転モード、機能と担当部品、機器間の接続、要求、検証ケースを管理します。「新規プロジェクト → MBSE仮想例（定格発電・冷間始動）」で、圧縮機抽気と翼冷却、油配管と軸受への接続を含む演習用の案件が開きます。

1. 運転モードを登録します。定格発電、冷間始動などについて、運用目的と成立条件を記入します。
2. 担当部品へ機能を割り当てます。機器間接続では送出側と受入側、必要に応じて両端の評価断面、受け渡す値と単位を指定します。接続図で流れ方向を確認できます。
3. 既存の要求に番号を付けるか、新しい要求を追加し、親要求、運転モード、部品、設計値、機能、接続を結び付けます。承認を記録するときは、要求の出典と適用モードも記入します。要求の内容・関係やモードを変更すると、以前と同じ承認記録は引き継がれません。
4. 要求ごとに検証ケースを追加し、適用モード、方法、検証手順と合否基準を指定します。定格正味電力（kW）、冷間始動の軸受A・Bの給油流量余裕（L/min）は、定格通しケースの詳細JSONを読み取り、要求値と比較できます。試験・検査・実演の資料は「資料」から登録し、確認値または手動判定を入力します。
5. 「判定を登録」で根拠を選び、運転条件と対象構成が一致することを確認します。仮想の根拠には「仮想」が付きます。判定履歴には設計版、根拠の版、運転条件、判定とファイルのSHA-256が残ります。

仮想例では、設計値の第1段対数全圧比分配は75%です。設計アプリ一式を利用している場合は、共通フォルダーの `artifacts/roadmap-completion-20261123/stage1-75/` にある `suite-report.json` と詳細JSON一式を同じ案件に取り込み、正味電力と軸受A・Bの流量余裕を登録できます。手元で計算する場合は、Cycle Studioの通しケース生成時に `--stage1-share 0.75` を指定します。前提の一致は登録者が確認してください。要求は演習用で、正味電力は73 kW以上、冷間給油は各軸受の流量余裕が0 L/min以上です。

「変更の影響を確認」で部品や設計値を選ぶと、関連する要求と検証が絞り込まれます。たとえば圧力比分配を変更すると、リンクした定格出力の判定が「再検証が必要」になり、給油条件に変更がなければ冷間始動の判定は継続します。機能や機器間接続の更新、派生要求でリンクした設計値・断面の変更も追跡します。要求値だけを変えた場合は、設計と運転条件が同じ解析結果から新しい基準で判定し直せます。検証ケースを削除した場合も、既存の判定は履歴から参照できます。

運転モード、要求・機能・接続、検証ケースの定義は案件のJSON書出しと複製で引き継ぎます。判定履歴と成果物原本を含めて保管する場合はSQLiteデータベースをバックアップしてください。

## 評価断面の設定

案件の「評価断面」タブで「段数・構成を設定」を押し、遠心圧縮機と軸流タービンの段数を入力します。初期値は圧縮機2段、タービン3段、圧縮機出口の90°転向・軸方向ガイドベーンありです。「断面区分」でガスタービン全体・圧縮機設計・タービン設計・燃焼器設計を切り替えます。

断面ごとにID、断面名、流れ順、対象部品、位置、評価量、座標・集計の条件を編集できます。全機のひな形は GasTurb 15 の発電用番号を使用し、Cycle Studio の位置IDを冷却有無別に記録できます。部品側には全機側の受渡し断面を指定できます。構成変更と断面は案件履歴と案件JSONに保存します。

前回の遠心2段構成に対応する[設定済み案件JSON](samples/two-stage-evaluation-stations.json)は、案件一覧の「JSONを取込」から開けます。位置の定義と照合方法は[評価断面の設定ガイド](EVALUATION_STATIONS.md)を参照してください。

## 設計成果物の登録

1. 案件を開いて「設計成果物」を選びます。
2. 「サイクル結果を取込」で Cycle Studio の計算ケース JSON または遠心2段設計レポート JSON を選びます。「翼形状を取込」では Blade Designer のプロジェクト JSON と対応する `.handoff.json` を選びます。各ファイルは5MBまでです。
3. 入力に使った設計版と対象部品を選んで登録します。案件全体の成果物は部品を「案件全体」にします。ファイルに登録先の情報がある場合は、その情報と選択内容が一致する必要があります。
4. 同じ案件・設計版に登録したサイクル結果と翼形状は、翼形状の受け渡し記録にある配分後のサイクル実行IDと入力ハッシュが一致すると紐付きます。一覧で概要と紐付けを確認でき、登録時のファイルをダウンロードできます。

同じ成果物を再取込すると既存の登録を返します。案件を更新すると、過去版に紐付く成果物は「再評価が必要」と表示されます。成果物の登録では設計版は進みません。成果物は案件の「JSONを書出し」や「設計案を複製」の対象外です。履歴と成果物をまとめて保管するには SQLite データベースをバックアップしてください。

### 定格通しケースの原本を保管

「定格通しケースを取込」で `suite-report.json` を選びます。原本も保管する場合は「詳細レポートのJSON一式」に、同じ出力フォルダーのうち要約を除く詳細JSONをすべて選択します。要約と原本は各5 MB、合計30 MB以内です。

要約が指定するファイル名、SHA-256、形式、入力元サイクルを照合して登録します。要約だけを先に登録した場合は、同じ設計版を指定して詳細レポートを追加できます。「詳細レポート一式ZIP」から、要約と原本を取得できます。

### 定格通しケースを比較

同じ案件に定格通しケースを2件登録し、それぞれに詳細JSONを付けます。「設計成果物」の「定格通しケースの比較」で基準ケースと比較ケースを選び、「運転点と結果を比較」を押します。

冷却連成後の圧縮機入口絶対全圧・全温・空気流量、回転数、計算モード、物性モデル、燃料条件を照合します。比較条件が一致すると、正味出力・燃料消費率・冷却空気流量と、同じ名称のシール隙間条件での軸受反力について「比較 − 基準」を表示します。

現行と異なる設計版には「再評価が必要」と表示します。同じ案件・設計版・サイクル実行ID・入力ハッシュに対応する遠心翼形状の差し替えは「対応する翼形状を再照合」と表示します。

設計アプリ一式では、共通フォルダーの `artifacts/suite-allocation-comparison-20261123/` にある均等配分案（`even/`）と第1段75%配分案（`stage1-75/`）を、各フォルダーの詳細レポートと一緒に取り込めます。

### 形状と全圧を評価断面で照合

「評価断面」で遠心圧縮機2段と対象の軸流タービン段数を設定します。出口の90°転向と軸方向ガイドベーンを含む6要素の圧縮機には、出口案内翼を含む構成を適用します。「設計成果物 → 評価断面照合を取込」で照合レポートを選ぶと、形状のSHA-256・評価断面ID・モデル全圧・CSV全圧を入力元の設計版に紐づけます。

登録した報告の「面積・絶対全圧と全圧損失」で、断面別の面積と全圧、および静止区間ごとの損失を確認できます。損失は入口と出口の両方に値がある場合に表示します。対応する遠心翼形状が登録済みなら原本を取得でき、形状を差し替えると報告が再評価対象になります。

設計アプリ一式での生成手順はCycle Studioの `DESIGN_TOOLS.md` を参照してください。共通フォルダーの `artifacts/station-review-20261123/station-review.json` に仮想ケースの照合レポートがあります。

定格通しケースに `support-review.json` がある場合は、「熱・二次空気・軸系」から温度、収束履歴、CSV照合、軸力、軸締結、給油とロータ応答を確認できます。詳細一式を登録した2ケースは、燃焼器出口パターンファクターや給油余裕も同じ比較表に表示されます。設計アプリ一式の起動・操作は、Cycle Studioの `SUITE_MANUAL.md` を参照してください。

### 2段圧縮機のCFD・試験性能比較を登録

1. 解析・試験に使った均等配分案と75%配分案の「翼形状JSON」と「.handoff.json」を、同じ案件・圧縮機部品・設計版に登録します。候補は手渡し記録の第1段対数全圧比配分（50%／75%）で選別されます。
2. Cycle Studioの「比較一式JSON」を、「性能比較を取込」で選びます。設計版と部品を設定し、解析・試験に使った翼形状を案ごとに指定します。対応付けは取込時の指定を記録するもので、CFDや試験の原データは出典欄から確認します。
3. 一覧の「両案の翼形状・出典・再計算結果」を開くと、共通運転条件、圧縮比仕事、正味出力、正味燃料消費率、翼形状のSHA-256を確認できます。比較一式、各案のサイクル結果、対応する翼形状と手渡し記録を取得できます。

同じ設計版・部品・配分で翼形状を改訂するときは、「翼形状を取込」で「差し替え元の翼形状」を選びます。その形状を使った比較に「再評価が必要」と表示され、以前の比較と形状も取得できます。差し替え元を空欄にすると、同じ配分の別案として追加します。

## 保存・履歴・バックアップ

- 各ダイアログの保存操作で `data/designs.sqlite3` に即時保存します。ブラウザを閉じても残ります。元ファイルや既存アプリのデータは変更しません。
- 保存はSQLiteトランザクションで行い、古いリビジョンからの上書きを拒否します。競合時は再読込してから編集し直してください。
- 「変更履歴」から過去の状態を復元できます。復元自体も新しい履歴になります。履歴の自動削除はありません。
- 部品を削除すると、その設計値を削除し、関連資料・リンクを案件全体に移します。添付登録の解除後も、過去の履歴を復元できるようファイル実体はDB内に残します。
- 案件は基本情報の状態を「保管」にして一覧から除外できます。「すべての案件」または「保管」で再表示できます。案件の完全削除は実装していません。
- 「JSONを書出し」は現在の設計情報と現在登録されている添付ファイルをまとめます。JSON取込は新しい案件として行い、元の案件を上書きしません。過去の履歴はJSONに含みません。
- 全案件・全履歴のバックアップは、アプリを終了してから `data/designs.sqlite3` をコピーしてください。復元時も終了してから戻してください。
- 添付ファイルは1件5MB、現行の登録合計は1案件30MBまでです。過去履歴・複製分を含め、DBのディスク使用量は増加します。添付は登録時のコピーで、元ファイルの変更には自動追従しません。
- DB・書出しJSONは暗号化していません。通常の設計ファイルと同様に保管・バックアップしてください。

## 今回の範囲

管理対象は設計情報です。計算実行、サイクル計算、CAD形状の生成・プレビュー、Blade Designer/RotorLabとの直接接続、単位換算、設計成立性の判定はまだありません。「確定」はユーザーが指定する管理上の状態です。

主流路図は部品の登録順を表示する概略図です。接続を定義する流路・軸ネットワークではありません。抽気・分岐などはメモ・資料に記録できます。

## 計算モジュールとの連携

`ARCHITECTURE.md` に共通データと追加方法を記載しています。案件・部品には安定したUUIDがあり、部品は案件内で識別します。計算コードは現在の管理画面から分離して追加できます。
