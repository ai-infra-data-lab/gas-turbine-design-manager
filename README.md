# Turbine Design Desk 0.1

ガスタービンの設計情報を案件・部品・設計案ごとに整理するローカルアプリです。計算機能は含みません。Python 3.10以上の標準ライブラリのみを使用し、追加パッケージ・アカウント・インターネット接続は不要です。

## GitHubから取得

```powershell
git clone https://github.com/ai-infra-data-lab/gas-turbine-design-manager.git gas_turbine_manager
cd gas_turbine_manager
python server.py
```

Python 3.10以上が必要です。公開版に個人の設計DB・試験用DBは含みません。数値入りの架空サンプルは `start_sample.bat` または `python create_samples.py` で生成できます。

独立した[一軸サイクル計算アプリ](https://github.com/ai-infra-data-lab/gas-turbine-cycle-app)もあります。現時点では直接接続せず、将来の連携用データ契約を用意しています。

## 起動

`start.bat` をダブルクリックします。ブラウザに `http://127.0.0.1:8770` が開きます。終了は起動したウィンドウで Ctrl+C です。別ポートの場合は `python server.py --port 8771` を使用します。

## 最初の操作

**数値入りサンプルと画像付きマニュアル**: `start_sample.bat` をダブルクリックすると、通常データと別のDBで2つの架空の設計案を開きます。サンプルURLは `http://127.0.0.1:8772/`。左メニューの「サンプル操作マニュアル」、または `docs/manual/index.html` から操作例を参照できます。

基準案Aは目標100 kW・60000 rpm、比較案Bは55000 rpmで、インペラ外径・効率目標にも違いを付けています。すべて操作説明用の架空値で、計算結果ではありません。初期値は `create_samples.py` で生成し、ブラウザで変更・保存・復元・添付の実演を行っています。既存のサンプルDBがある場合は上書きしません。`samples/A_基準案.json` と `samples/B_低回転案.json` は、通常アプリへ取り込める添付込みの初期データです。DBの履歴はJSONには含まれません。

1. 「新規プロジェクト」で案件名を入力します。「一軸ガスタービン」を選ぶと8部品と未設定の要求項目を作成します。計算値・架空の性能値は生成しません。
2. 「基本情報を編集」で用途、構成、担当、目的、状態を記録します。
3. 「部品構成」で部品を追加・編集・並べ替えます。部品を選択すると、その部品の「仕様・設計値」が開きます。
4. 仕様・設計値は項目名、値、単位・定義、出典・根拠、備考を登録します。値は文字列で、空欄や範囲も扱えます。単位換算・妥当性判定は行いません。
5. 「資料」でファイルのコピーや参考URLを登録します。関連部品も指定できます。「案件全体」では全資料、「部品」ではその部品の資料を表示します。
6. 「設計メモ」で判断理由・検討事項などを残します。
7. 「設計案を複製」で代替案を作り、「設計案の比較」で基本情報・要求仕様・部品情報・部品設計値を比較します。

## 保存・履歴・バックアップ

- 各ダイアログの保存操作で `data/designs.sqlite3` に即時保存します。ブラウザを閉じても残ります。元ファイルや既存アプリのデータは変更しません。
- 保存はSQLiteトランザクションで行い、古いリビジョンからの上書きを拒否します。競合時は再読込してから編集し直してください。
- 「変更履歴」から過去の状態を復元できます。復元自体も新しい履歴になります。履歴の自動削除はありません。
- 部品を削除すると、その設計値を削除し、関連資料・リンクを案件全体に移します。添付登録の解除後も、過去の履歴を復元できるようファイル実体はDB内に残します。
- 案件は基本情報の状態を「保管」にして一覧から除外できます。「すべての案件」または「保管」で再表示できます。案件の完全削除は実装していません。
- 「JSONを書出し」は現在の設計情報と現在登録されている添付ファイルをまとめます。JSON取込は新しい案件として行い、元の案件を上書きしません。過去の履歴はJSONに含みません。
- 全案件・全履歴のバックアップは、アプリを終了してから `data/designs.sqlite3` をコピーしてください。復元時も終了してから戻してください。
- 添付ファイルは1件5MB、現行の登録合計は1案件30MBまでです。過去履歴・複製分を含め、DBのディスク使用量は増加します。添付は登録時のコピーで、元ファイルの変更には自動追従しません。
- DB・書出しJSONは暗号化していません。通常の設計ファイルと同様に保管・バックアップしてください。

## 今回の範囲

管理対象は設計情報です。計算実行、サイクル計算、CAD形状の生成・プレビュー、Blade Designer/RotorLabとの直接接続、単位換算、設計成立性の判定はまだありません。「確定」はユーザーが指定する管理上の状態です。

主流路図は部品の登録順を表示する概略図です。接続を定義する流路・軸ネットワークではありません。抽気・分岐などはメモ・資料に記録できます。

## 将来の計算モジュール

`ARCHITECTURE.md` に共通データと追加方法を記載しています。案件・部品には安定したUUIDがあり、部品は案件内で識別します。計算コードは現在の管理画面から分離して追加できます。
